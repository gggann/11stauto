# 项目需求文档：千万级商品任务分配系统 - QC 管理后台开发

## 1. 项目背景 (Project Context)
- **现状**：系统已部署 PostgreSQL 数据库和基础 RESTful API，前端已实现基本框架。
- **核心业务**：系统处理几千万条商品数据，并将其自动分配给约 20 名员工进行处理。
- **痛点**：由于从早期的“共享文档”转向了“数据库+API”架构，品质管理人员（QC）失去了全量查看数据、手动干预任务和修改错误的能力。

## 2. 技术栈 (Tech Stack)
- **数据库**: PostgreSQL (处理千万级数据量)
- **后端**: RESTful API
- **前端**: 已有前端框架 (需扩展管理界面)

## 3. 核心功能需求 (Functional Requirements)

### A. 品质管理 (QC) 全量看板
- **高频率分页查询**：由于数据量达千万级，必须实现高效的后端分页（Offset/Limit 或 Keyset Pagination）。
- **多维度筛选**：支持按商品 ID、员工姓名、任务状态（待处理、进行中、已完成）、更新时间进行过滤。
- **实时统计**：在页面顶部显示当前任务进度统计（例如：总数、已分配数、剩余数）。

### B. 手动干预与修改功能
- **任务重分配**：QC 可以选中一个或多个任务，手动将其分配给指定的员工（需调用 API 进行 `PATCH` 操作）。
- **数据回滚/状态修改**：允许 QC 手动重置任务状态（如将“已完成”改为“需重做”）。
- **手动锁定**：增加一个 `is_manually_assigned` 字段，防止自动分配算法覆盖 QC 的手动干预结果。

### C. 并发安全与性能优化
- **行级锁机制**：在自动分配逻辑中，请使用 `SELECT ... FOR UPDATE SKIP LOCKED` 确保多个分配进程不会冲突。
- **索引建议**：请根据查询频率对 `status`, `assignee_id`, `created_at` 等关键字段建立复合索引。

## 4. 待开发任务清单 (To-do List for AI)

### 第一步：数据库 Schema 增强
- 建议增加 `audit_logs` 表，记录 QC 的所有修改操作（操作人、时间、旧值、新值）。
- 在商品表增加 `priority` (优先级) 和 `is_manually_assigned` 字段。

### 第二步：API 接口开发
- `GET /api/admin/tasks`：支持大规模数据分页和多条件筛选。
- `POST /api/admin/tasks/batch-assign`：实现批量任务重分配逻辑。
- `GET /api/admin/statistics`：高效统计各状态任务数量。

### 第三步：前端 QC 管理页面
- 使用高性能表格组件（支持虚拟滚动或后端分页）。
- 集成批量操作工具栏（批量指派、批量修改状态）。
- 实现简单的修改日志展示弹窗。
